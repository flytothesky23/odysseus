# v0.1.8-ko

This patch restores management reports to the traditional report style while preserving the wide-table readability fix from `v0.1.7-ko`.

## Highlights

- Keeps `경영분석` report introductions as normal narrative Markdown lists instead of automatically converting the first list into large KPI cards.
- Removes management-only dashboard decoration such as the ledger-grid background, section-card rails, strong colored table headers, and first-column highlight treatment.
- Preserves the management-report desktop width expansion and `.table-scroll` wrapper for wide route, KPI, and decision tables.
- Adds a regression assertion that the first management summary list remains a normal list and is not styled through a generic `ul:first-child` grid selector.
- Verifies the rendered HTML with a Playwright smoke check: first list is `display: block`, section headings have no custom card rail, and the wide table still scrolls horizontally.

## Why

The user asked for wide tables to stop compressing Korean table columns into one-character stacks. The `v0.1.7-ko` table fix succeeded, but the accompanying visual treatment changed the report opening into a dashboard-like layout. That made the report feel like a gimmick instead of a written management report.

This patch narrows the visual change back to the actual problem: tables should stay readable, while the rest of the report should follow the normal document flow. Statistical charts are a separate feature because they need explicit data extraction, axis selection, units, and period normalization instead of CSS-only decoration.
